**目标**：当前 prompt hook 已有"基础脱敏审计记录"（HANDOFF），但没有可导出/可筛选的审计数据。本任务把审计记录落成一个可导出的结构化文件，作为"完整审计面板"的前置（不实现 UI 面板，只做数据出口）。

**背景事实**（已核实）：
- HANDOFF："前端会记录脱敏后的 hook 请求/响应、插件 ID、事件名、耗时、错误摘要和 payload hash/长度"。
- 相关前端文件：`frontend/src/utils/promptHooks.js` 和 `frontend/tests/prompt-hooks.test.mjs`。
- HANDOFF 明确：**可以说"基础脱敏审计已记录"，不可说"完整审计面板/导出已完成"**。本任务就是把"导出"从 0 做到 1。

**步骤**：

1. 读 `frontend/src/utils/promptHooks.js`，找到审计记录的数据结构（hook 请求/响应/插件 ID/事件名/耗时/错误/hash/长度存在哪——是内存数组还是 store）。
2. 读 `frontend/tests/prompt-hooks.test.mjs`，确认现有测试覆盖了哪些审计字段。
3. 设计一个导出函数 `exportPromptHookAudit()`（放 `frontend/src/utils/promptHooks.js` 或新文件 `frontend/src/utils/promptHookAudit.js`），把审计记录序列化成 JSON，字段至少含：`timestamp` / `pluginId` / `eventName` / `durationMs` / `errorSummary` / `payloadHash` / `payloadLength` / `redactedRequest` / `redactedResponse`。
4. 提供一个触发点：在 DebugDrawer 或 PluginPanel 加一个"导出 prompt hook 审计"按钮（参考现有导出 bundle 的按钮写法，`grep -n "export\|download\|blob" frontend/src/components/DebugDrawer.vue`）。如果加按钮有风险或组件结构复杂，退一步：只导出函数 + 测试，按钮留到下一任务并在记录里说明。
5. 写测试 `frontend/tests/prompt-hook-audit.test.mjs`（或在现有 `prompt-hooks.test.mjs` 加用例），覆盖：脱敏（请求/响应里不能出现真实 prompt 全文，只能是 hash/长度）、字段完整、空审计时导出空数组不报错。
6. `cd frontend && npm test && npm run build`。

**脱敏硬规则**：导出数据里**绝不能**包含完整 prompt 或完整 LLM payload原文——只能是 hash + 长度 + 极短的错误摘要。测试里要断言这一点（用一个已知 prompt，导出后 grep 不到原文）。

**验证**：

```bash
cd frontend && npm test
cd frontend && npm run build
# 抽查：测试里有断言"完整 prompt 原文不出现在导出里"
git grep -n "redact\|hash\|length" frontend/tests/prompt-hook-audit.test.mjs
```

**完成标准**：导出函数 + 测试存在、脱敏断言通过、构建成功。在 `### 执行记录` 里诚实写"是否加了 UI 按钮"。
